            How each provider supplies subtitles

            MovieBox — two signed BFF endpoints, same auth headers as streams: GET /wefeed-mobile-bff/subject-api/get-stream-captions?subjectId=..&streamId=.. and GET /wefeed-mobile-bff/subject-api/get-ext-captions?subjectId=..&resourceId=..&episode=0. Both return data.extCaptions[] of {url, lanName?/language?/lan?}; label = English(lang tag) + " (audioLanguage)"; files are usually .srt (CloudFront-signed or plain).

            CastleTV — every film-api answer is base64(AES-128-CBC); key = first 16 bytes of base64decode(getSecurityKey().data) + "T!BgJB", IV = key. Episode details (/film-api/v1.9.9/movie) carry episodes[].subtitles[] ({title, abbreviate, url, isDefault, isAI}), .vtt files on img1.bhcxy.com / fhxod / fodcyy. getVideo2 only needed when the details list is empty, and accepts internal resolution codes "2"/"1" only.

            4KHDHub — no subtitles at all: the subtitleCallback is only threaded through the HubCloud / Hubdrive / Hblinks / HUBCDN extractors and none of them emit a SubtitleFile.
